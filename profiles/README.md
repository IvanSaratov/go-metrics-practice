
## Бенчмарки

Запуск из корня проекта:

```bash
go test ./internal/repository ./internal/agent ./internal/handler -run '^$' -bench . -benchmem
```

| Бенчмарк | Что измеряет |
| --- | --- |
| `BenchmarkMemStorage` | Обновление пакета метрик, чтение одной и всех gauge-метрик |
| `BenchmarkFileStorage` | Обновление пакета без немедленной записи и с синхронной записью в файл |
| `BenchmarkAgent` | Создание снимка метрик и сжатие JSON в gzip |
| `BenchmarkServer` | Обновление пакета, получение метрики и страницы со списком метрик |


Профили двух замеров до и после оптимизации кода gZip сохранены в `profiles/base.pprof` и `profiles/result.pprof`.

На `encodeGzipJSON` вместе с вызываемыми функциями приходилось 99% выделенной памяти. Основная причина — создание нового gzip-переменной при каждом кодировании. Теперь `gzip` повторно используется через `sync.Pool`. 

### Результаты

| Показатель профиля | До | После |
| --- | ---: | ---: |
| Суммарно выделено памяти (`alloc_space`) | 779,56 МиБ | 4,16 МиБ |
| Выделено объектов (`alloc_objects`) | 41 534 | 23 884 |
| Удерживаемая память (`inuse_space`) | 13,49 КиБ | 821,98 КиБ |

Суммарный объём выделений уменьшился на 99,47%. Удерживаемая память выросла: пул сохраняет компрессор и его внутренние буферы для следующих вызовов.

Сравнение профилей:

```bash
pprof -top -diff_base=profiles/base.pprof profiles/result.pprof
```

| Показатель `EncodeGzipJSON` | До | После |
| --- | ---: | ---: |
| Время, медиана (`ns/op`) | 45 886 | 35 380 |
| Выделено памяти (`B/op`) | 814 794 | 904–928 |
| Количество аллокаций (`allocs/op`) | 22 | 5 |

Время в этом замере сократилось примерно на 23%.

Все тесты проводились на Macbook M4.
